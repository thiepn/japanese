## Automated CI is a protected BLOCKED decision

\`scripts/j26-independent-release-authority.mjs\`, with \`J26_CANDIDATE_SHA\`, reads actual J23/J24/J25 machine records, checks all belong to the *same exact candidate*, verifies the J25 requirement for **42 original visual cases / 126 PNGs**, checks the J15D signoff, J16 field and P22 production manifests remain unsigned and not activated, and writes \`artifacts/j26-protected-release-decision.json\`.

A clean CI has the non-authorizing state \`BLOCKED_MISSING_INDEPENDENT_APPROVAL_AND_CUTOVER_AUTHORITY\`, \`releaseAuthorized:false\`, \`mergeAuthorized:false\`, \`deploymentAuthorized:false\`. It is an automated **gate consistency** result, not a successful human acceptance. There is no code path that performs a merge, deployment, OAuth registration or screenshot-baseline update.

## Independently verified evidence remains external

For real operator intake, J24 already validates all nine categories of original evidence: 42-case/126-PNG visual archive and independent visual review, physical Android/PWA/TalkBack plus speaker/headphones/microphone, first-party THIEPN Account OAuth Chrome/PWA callbacks, qualified Japanese and P11 reviews, accessibility, exact staging identity and witnessed rollback. J25 then requires externally pinned fresh revocations, trusted Ed25519 signer keys, independence and two operator endorsements. **Both steps must be run against authentic source evidence on an operator-controlled workstation.** Synthetic fixtures are not acceptable.

J26 can inspect a returned J25 admission receipt but **cannot** authenticate it without its underlying separately verified artifact and trust root. Even after a passing cryptographic J26 inspection, release authorization is still false. The final production decision must be explicitly made and logged by the appropriate independent release authority outside source-branch CI.

## Separate four-role human approval package

J26 introduces an *additional* independently maintained Ed25519 approval roster for four distinct roles: **product, accessibility, release-operations, independent-audit**. Supply the roster's original SHA-256 fingerprint through a separate trusted channel, not through the approval file itself. Each reviewer entry requires a unique Ed25519 key fingerprint, identity evidence digest, \`identityAuditedByOperator:true\`, independence declaration, non-revocation, authorized role and a valid key lifetime. Signers cannot overlap with the J24 primary evidence signers.

The approval package is \`thiepn-japanese-j26-independent-approval-package\`. It must bind the exact candidate SHA, canonical JSON digest of the actual J25 receipt, decision context SHA-256, original visual packet SHA-256, reviewed-language evidence digest, staging SHA, distinct known-good rollback commit, 42 cases, 126 images, approval request/expiry dates, and four detached role-specific signatures. Signatures cover the canonical message generated by \`approvalPayload\` with disposition \`ACKNOWLEDGE_EVIDENCE_ONLY_NO_AUTOMATIC_CUTOVER\`.

The offline CLI (access-controlled machine only):

\`\`\`sh
J26_CANDIDATE_SHA=<exact-tested-sha> \
J26_APPROVAL_ROSTER_SHA256=<externally-verified-sha256> \
J26_EXISTING_EVIDENCE_SIGNERS_JSON='["actual-evidence-signer-id", "..."]' \
node scripts/j26-independent-release-authority.mjs \
  --inspect-approval /restricted/approval-package.json \
  --admission /restricted/j25-admission-receipt.json \
  --roster /restricted/pinned-approval-roster.json
\`\`\`

Successful structural verification returns a receipt with \`fourIndependentSignaturesValid:true\` and \`WAITING_FOR_EXPLICIT_SEPARATE_RELEASE_AUTHORITY\`. It **does not** assert that the names, real Android observations, Google OAuth callbacks, original screenshots or rollback were actually verified by this script and it does not grant deployment authority. No private keys, real account tokens, personally identifiable learner content, recordings, private reviewer replies or signed production approvals belong in this draft source branch.
