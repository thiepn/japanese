## Independent external intake verifier

\`inspectExternalPacket\` is offline only. It must receive the exact candidate's J27–J31 source reports and separately obtained **externally pinned** real inputs:
1. A fully checked original **J31 external nine-gap handoff** (all independently pinned handoff receipts, signer roster, fresh revocations, replay ledger and two separately scoped Ed25519 custody signatures). J32 actually re-runs \`inspectExternalHandoff\`; a machine JSON "passed" string is insufficient.
2. A separately pinned \`thiepn-japanese-j32-primary-source-packet\`, version 1, candidate SHA and J31 canonical report digest, unique 32-character lowercase-hex \`batchId\`, 9 unique domain records, \`purpose:"UNAPPROVED_EVIDENCE_INTAKE_ONLY"\`, and ALL authorization fields explicitly false.
3. A separately pinned external \`thiepn-japanese-j32-external-reviewer-roster\`, version 1, min 11 fingerprinted Ed25519 keys, one distinct per domain and separate sender/receiver custody roles. Keys/identities cannot be reused from the J31 roster. Self-asserted independence and identity audit flags are claims; authorized people must verify real identities outside this software.
4. A separately pinned \`thiepn-japanese-j32-external-revocations\` snapshot valid for at most 24h, an independently current \`thiepn-japanese-j32-replay-ledger\` of batches/packet digests and an externally pinned preceding roster SHA. A dual-signed \`thiepn-japanese-j32-intake-transfer\` binds the exact packet, J31 digest, previous/current custody roots, revocations, two different operators and time window. Nothing in source-control can become a trusted key by itself.
5. For each domain record: \`kind\`, \`sourcePath\` under \`evidence/<safe-file>.json\`, \`sourceSha256\`, \`sourceBytes\`, \`signerId\`, \`reviewedAt\`, \`expiresAt\`, \`humanAccepted:false\`, and a detached Ed25519 \`signature\` over exact \`reviewPayload\`. The source bytes must hash exactly and declare \`SUBMITTED_NOT_INDEPENDENTLY_ACCEPTED\`. Eight nonvisual domains must include explicit unsigned required witness procedures and original source provenance; claims alone never count as completed real-world tests.
6. For the visual domain: an original archive manifest schema \`thiepn-japanese-j32-original-visual-inventory\`, exactly 42 ordered unique \`VIS-###\` mapping slots and 126 ordered \`PNG-###\` mapping slots, each with a genuine *externally established* original filename, own distinct safe relative path \`original/<file>.png\`, raw PNG SHA256 and length, mapping to a case, human-comparison/approval false. **All 42 cases must be represented by at least one of the 126 original PNGs.** Raw image bytes are read and checked against the digest and PNG signature. That is *byte integrity only*, not proof that 126 files are genuinely original or that visual comparisons passed.

A successful signed source admission reports 135 structurally consistent source files (126 PNGs + 9 domain primary records), nine **structurally** verified submissions, 42 mapped case slots, and **0 human approvals**. It proposes an append to the independent replay ledger but never writes it. An independently pinned stale ledger can still permit concurrent replay until the external append-only store atomically consumes each batch.
